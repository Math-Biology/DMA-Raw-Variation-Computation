# DMA — Raw Variation & Oscillations

**Component codes:** `raw_variation` `#L001-U015-P26.0234` · `oscillations` (see `oscillations/CLAUDE.md`)

This repository hosts two distinct but chained stages of the DMA (Digital Medicine
Analyzer) pipeline. Each stage is self-contained — its own dependencies, tests and
configuration — and is run and tested from its own folder.

- **Stage 1 — `raw_variation`** (repo root): computes the percentage variation of
  each biological marker relative to the baseline measurement, from the consolidated
  multi-sheet Excel export. Produces `Output/all_visits_percentage_variation.csv`.
- **Stage 2 — `oscillations/`**: computes the oscillation δ for every
  `(visit, anatomical point)` pair from the raw percentage variations, and compiles
  a PDF report.

**Data dependency between the stages:** Stage 2 consumes the
`all_visits_percentage_variation.csv` produced by Stage 1. Copy that file into
`oscillations/data/input/` before running the second stage. The cohort splits
`F_visits_percentage_variation.csv` and `M_visits_percentage_variation.csv` follow
the same convention.

## Stage 1 — raw_variation

Computes the percentage variation of each biological marker relative to the baseline
measurement for DMA visit data. Accepts a consolidated multi-sheet Excel export as
primary input and produces two global CSV files in long (tidy) format.

### How it works

For each visit sheet in `exported_visits.xlsx`, the module:

1. Extracts visit metadata (patient ID, visit ID, visit date) from the first data row
2. Reconstructs the measurement table, dropping padding columns and converting string values to numeric
3. Identifies the baseline for each measurement point as the minimum positive value across all rows
4. Computes the percentage variation of each marker row relative to that baseline:
   `variation = (value − base) / base × 100`
5. Appends both the original and the variation rows — in long format — to two global accumulators
6. Writes two CSV files to `Output/`:
   - `all_visits_original.csv` — raw measurements including the Base row
   - `all_visits_percentage_variation.csv` — percentage variations, Base row excluded

### Input format (`exported_visits.xlsx`)

Each sheet is named `Visita_N` and contains:

| Excel row | Content |
|---|---|
| Row 1 | Column headers read by pandas: `Patient ID`, `First Name`, `Last Name`, `Gender`, `Age at Visit`, `Date of Birth`, `Visit ID`, `Visit Date` |
| Row 2 | Visit/patient metadata values |
| Row 3 | Measurement table headers: `Marker` + point names (e.g. `LH - 3 - e [9]`) |
| Row 4 | `Base` + baseline conductance values (stored as strings) |
| Rows 5+ | Biological markers + conductance values (stored as strings) |

Columns beyond the measurement points are NaN padding and are dropped automatically.

### Output format

Both CSV files use **long format** — one row per `(visit, marker, point)` triple:

`all_visits_original.csv`:
```
visit_id, patient_id, visit_date, marker, point, value
```

`all_visits_percentage_variation.csv`:
```
visit_id, patient_id, visit_date, marker, point, percentage_variation
```

### Entry points

| Function | Input | Output | Status |
|---|---|---|---|
| `run_exported()` | `Input/exported_visits.xlsx` | Two global CSVs | **Primary** |
| `run()` | `Input/<visit>/` folder structure | Per-sheet `.xlsx` files | Legacy, kept for backward compatibility |

`python raw_variation.py` calls `run_exported()`.

### Configuration

`config.xml` parameters used by `run_exported`:

```xml
<file_config>
    <input_path>./Input/</input_path>
    <output_path>./Output/</output_path>
    <exported_visits_file>exported_visits.xlsx</exported_visits_file>
</file_config>
<it_config>
    <original>original</original>
    <percentage_variation>percentage_variation</percentage_variation>
</it_config>
```

The `<visit_config>` thresholds and the remaining `<it_config>` keys (`new_base`,
`fane_values`, `visual_correction`, `bmri`, `final_report`) are reserved for
downstream pipeline components and are not applied by this module.

## Stage 2 — oscillations

Computes the oscillation δ for every `(visit, anatomical point)` pair from the raw
percentage variations produced by Stage 1. No corrective rules are applied to the
input; δ is the final output. After each run a PDF report is compiled automatically.

### Core formula

```
δ = max(positive_values) − min(positive_values)
```

`positive_values` = all values in the series strictly greater than 0 (zeros and
negatives excluded). Returns `0.0` if fewer than two strictly positive values exist.
δ is expressed in percentage points. See `oscillations/oscillation_formula.md` for the
full specification and traceability references.

### Input

Long-format CSV with one row per `(visit, marker, anatomical point)` triple — the
Stage 1 output — with columns `visit_id, patient_id, visit_date, marker, point,
percentage_variation`.

### Output

Three cohorts are processed (`All`, `F`, `M`), each written under its own folder in
`oscillations/data/output/` (`output_All`, `output_F`, `output_M`). For each cohort:

- an **oscillation CSV** — one row per `(visit, anatomical point)`, column `oscillation_%`
- a **median-by-point CSV** — one row per anatomical point, column `median_oscillation_%`
- a **PDF report** (`report/oscillation_report.pdf`) — dataset summary, a ranked bar
  chart of median δ per anatomical point, and the full median-by-point table

### Usage

```bash
cd oscillations

# explicit input/output paths (one run per cohort)
python run_oscillation.py data/input/all_visits_percentage_variation.csv \
    data/output/output_All/all_visits_percentage_variation_oscillations.csv
```

Compiling the PDF report requires a working `pdflatex` (TeX Live / MacTeX). See
`oscillations/CLAUDE.md` for the full module reference.

### Testing

```bash
cd oscillations
python -m pytest tests/ -v
```
